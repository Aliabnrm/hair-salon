# ADR-001 — انتخاب فناوری
نسخه ۰٫۲ — ۲۰۲۶-۱۰-۲۹

وضعیت: **بک‌اند اسپرینت ۱ اجراشده؛ PostgreSQL و محدوده پایه اسپرینت ۲ تأییدشده؛ فرانت پیشنهادی**. طرح دقیق و ابزار DB در ADR-004 مشخص شدند و هنوز نصب/تست اسپرینت ۲ انجام نشده است. پیشنهاد نسخه ۰٫۱ مبتنی بر Next.js full-stack با انتخاب صریح NestJS جایگزین شد؛ مهاجرتی از کد آن گزینه وجود ندارد.

| بخش | انتخاب/پیشنهاد | وضعیت و دلیل |
|---|---|---|
| بک‌اند | NestJS | پذیرفته‌شده؛ درخواست مستقیم کارفرما برای پیاده‌سازی و یادگیری ساختار بک‌اند |
| زبان بک‌اند | TypeScript با strict mode | در محدوده اسپرینت ۱ تأییدشده؛ تنظیم و نسخه دقیق مطابق ADR-003 |
| معماری بک‌اند | Modular Monolith، ماژول‌بندی بر اساس قابلیت | قرارداد جاری ADR-002 بر اساس درخواست معماری منسجم؛ لایه‌ها متناسب پیچیدگی |
| دیتابیس | PostgreSQL 17.x | پایه اسپرینت ۲ تأییدشده؛ patch/image و سازگاری واقعی در اجرا طبق ADR-004 ثبت شوند |
| ابزار دیتابیس | Drizzle + node-postgres، migration با Drizzle Kit | انتخاب اجرایی پس از مقایسه Prisma/TypeORM؛ دلیل ADR-004؛ نصب و اثبات سازگاری هنوز انجام نشده |
| فرانت‌اند | React/Next.js، TypeScript | پیشنهاد؛ پس از دریافت فایل/کد فیگما و بررسی نیاز SSR/SEO نهایی شود |
| runtime و package manager | Node 24.22.2 LTS و npm 11.19.1،workspaces و lockfile واحد | نصب تکرارپذیر و بررسی واقعی اسپرینت ۱ مطابق ADR-003 |
| آزمون بک‌اند | Vitest 4.1.12 و Supertest با @nestjs/testing | جایگزین پیشنهاد قبلی Jest؛ boot واقعی و تست‌های HTTP اسپرینت ۱ اجرا شدند؛ جزئیات ADR-003 |
| SMS، میزبانی، object storage و CI provider | TBD | ارزیابی دسترسی ایران، هزینه، شرایط خدمات و قابلیت مهاجرت |

NestJS یک ساختار برای controller، provider و dependency injection فراهم می‌کند؛ معماری دامنه و صحت رزرو باید جداگانه طراحی شوند. Nest به‌تنهایی صحت، امنیت یا مقیاس‌پذیری را تضمین نمی‌کند.

ساختار پیشنهادی یک مخزن با apps/api و بعداً apps/web است؛ Nx/Turborepo و shared package تا نیاز واقعی اضافه نمی‌شوند. بک‌اند یک واحد استقرار دارد؛ فرانت و worker در صورت ورود به دامنه می‌توانند فرایند جدا باشند. نیاز به Redis، message broker یا چندسرویس پس از اندازه‌گیری بررسی شود.

گزینه‌های تاریخی: Next.js full-stack زبان مشترک و اجزای کمتر داشت؛ Django و Laravel برای تیم ماهر خود گزینه‌های معتبر بودند. ترجیح فعلی کارفرما یادگیری و ساخت بک‌اند مستقل Nest است؛ ساختار روشن و آموزش‌پذیری مزیت آن و هزینه بیشتر قرارداد و اتصال فرانت/بک‌اند نقطه‌ضعف آن است. با API مستند، آزمون اتصال و ماژول‌های کوچک ریسک کاهش می‌یابد.

تصویب مرحله‌ای: تأیید اسپرینت ۱ فقط ابزارها و ساختار همان اسپرینت را مصوب می‌کند؛ ORM، دامنه خدمات، پرداخت یا استقرار production خودکار مصوب نیستند. انتخاب‌های بعدی در این ADR یا ADR مستقل با دلیل و پیامد ثبت شوند.
