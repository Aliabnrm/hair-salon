# ADR-007 — مدیریت خصوصی سالن و امنیت مالک

**اصلاح تصمیم:** بخش‌های MFA/assurance این ADR به دستور کارفرما با [ADR-008](ADR-008-remove-owner-mfa.md) جایگزین شدند. توضیح آن‌ها در پایین سابقه تصمیم اولیه است؛ پیاده‌سازی جاری فقط ورود ایمیل/رمز و مجوز مالک را لازم دارد. تصمیم‌های سالن/tenant/transaction این ADR برقرارند.

تاریخ: ۲۰۲۶-۱۱-۰۱؛ وضعیت: پذیرفته‌شده در محدوده اسپرینت ۴ با درخواست صریح کارفرما برای اجرای کامل طرح و چهار تصمیم S4-D01..04. این تصمیم انتشار عمومی یا رزرو را تصویب نمی‌کند.

## زمینه و تصمیم

حساب ایمیل/رمز موجود برای مشتری کافی است، اما مدیریت داده سالن به احراز قوی‌تر و مجوز مستقل نیاز دارد. `identity` صاحب MFA و نشست؛ `salon-management` صاحب Business، عضویت مالک، خدمات، متخصص و برنامه کاری است. معماری همان Modular Monolith و feature-first در ADR-002 می‌ماند. چهار Store برای مرز واقعی PostgreSQL داریم؛ GenericRepository، سرویس جدا، CQRS یا ابزار state تازه لازم نشد.

سالن تک‌محل، خصوصی و `draft` است؛ مخاطب هر سالن `men|women` و زمان `Asia/Tehran`. متخصص حساب کاربری ندارد. خدمت پیوسته و تک‌متخصص است. مبلغ API/DB عدد صحیح IRR، UI تومان؛ تاریخ روز خاص در API میلادی ISO و UI شمسی است. هیچ اتصال به discovery نمونه یا تولید وقت آزاد انجام نمی‌شود.

## امنیت و داده

- TOTP با OTPAuth 9.5.2، SHA1/شش رقم/۳۰ ثانیه/پنجره ±۱؛ پذیرش گام زمانی باید اکیداً پس از آخرین گام باشد. قفل User سپس Session مصرف هم‌زمان گام و recovery را سری می‌کند.
- راه‌اندازی نیازمند grant احراز مجدد رمز، وابسته به همان actor/session، با اعتبار پنج دقیقه و مصرف یک‌بار است. pending ده دقیقه؛ عامل فعال جایگزین نمی‌شود. فعال‌سازی، recovery و ارتقای نشست یک transaction هستند.
- secret با AES-256-GCM، nonce تصادفی و AAD کاربر/هدف نگهداری می‌شود؛ envelope دارای شناسه نسخه/کلید `v1` است. این نسخه فقط یک کلید فعال دارد و key rotation عملیاتی هنوز اجرا نشده است. recovery از ۳۲ بایت تصادفی و HMAC با کلید مستقل استفاده می‌کند؛ کد خام فقط یک‌بار در پاسخ خصوصی می‌آید.
- config کلید غایب را برای سازگاری ورود معمولی مجاز می‌داند، اما عملیات نیازمند کلید با 503 بسته می‌ماند. کلید حاضر باید hex دقیق ۳۲ بایت باشد؛ دو کلید یکسان در startup رد می‌شوند. این سیاست bypass MFA ایجاد نمی‌کند. backup کلیدها پیش از استفاده مشترک ضروری است؛ بازتولید کلید قبلی را بازیابی نمی‌کند.
- assurance به همان نشست تعلق دارد: هشت ساعت مطلق و سی دقیقه idle؛ فقط درخواست مدیریت موفق idle را جلو می‌برد. primary session همچنان باید زنده باشد.
- مجوز مالک در سرور و دوباره داخل transaction بررسی می‌شود؛ child query با business_id محدود و ارتباط‌های staff/service/exception با FK مرکب محافظت می‌شوند. RLS فعال نشده است.

## هم‌زمانی و قرارداد write

همه writeهای مدیریت کلید intent دارند؛ کلید، operation و actor زیر advisory lock بررسی می‌شوند، سپس Business و در صورت نیاز Staff قفل می‌شوند. ایجاد سالن روی User قفل دارد تا سقف سه سالن در رقابت رعایت شود. effect، audit و نتیجه idempotency با هم commit/rollback می‌شوند. مجوز فعلی پیش از replay دوباره بررسی می‌شود. پاسخ تا هفت روز می‌ماند؛ پس از آن fingerprint باقی می‌ماند و تکرار قدیمی 409 می‌گیرد. پاکسازی payload محدود است، worker تازه نداریم.

`If-Match: "version"` جلوی overwrite نسخه کهنه را می‌گیرد؛ replay همان intent پیش از مقایسه نسخه پاسخ قدیم را برمی‌گرداند. version تنظیمات، خدمت، متخصص و ساعات مستقل است. شمارنده نرخ اتمیک PostgreSQL و bounded cleanup دارد؛ سهمیه پشت proxy فعلی بین peerهای آن مشترک است.

بازه‌ها relational و دقیقه محلی هستند؛ exclusion واقعی PG مانع overlap است. partial unique index روز خاصِ سالن با staff_id=null را پوشش می‌دهد. deferred trigger هنگام commit تعداد/سازگاری بازه‌های استثنا را کنترل می‌کند. audit append-only است. این SQLهای تکمیلی در migration افزایشی 0002 و خارج از قابلیت بیان snapshot Drizzle نگهداری می‌شوند؛ snapshot جای مرور SQL را نمی‌گیرد.

## گزینه‌ها و پیامدها

SMS هزینه و تأمین‌کننده انتخاب‌شده ندارد؛ برای این برش TOTP مستقل از شبکه انتخاب شد. QR و provider بیرونی لازم نشد؛ ورود دستی Authenticator ارائه شده است. کتابخانه تقویم jalaali-js 2.0.1 فقط برای تبدیل معتبر انتخاب شد؛ Intl برای نمایش کافی است، برای تبدیل معکوس ورودی کافی نیست.

قفل Business ساده و قابل آموزش است، اما writeهای یک سالن را سری می‌کند؛ ظرفیت نامحدود یا benchmark ادعا نمی‌شود. در مرورگر همان transport/session موجود، hook داده و mutation و توابع خالص تبدیل استفاده شدند. قطع پاسخ کلید intent را حفظ می‌کند؛ پاسخ secretدار MFA cache عمومی ندارد.

تغییر/حذف عامل، reset رمز و recovery پشتیبانی هنوز وجود ندارند؛ UI این محدودیت را اعلام می‌کند. انتشار عمومی، راستی‌آزمایی قانونی، trusted proxy، آزمون بار و مدیریت عملیاتی کلیدها تصمیم بعدی می‌خواهند.
