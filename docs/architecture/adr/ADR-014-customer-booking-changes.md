# ADR-014 — تغییر اتمیک همان نوبت

۲۰۲۶-۱۱-۰۶؛ مصوب در اسپرینت۸. لغو مشتری تا دو ساعت پیش از شروع و جابه‌جایی در همان خدمت/سالن افزوده می‌شود. مقصد حداقل دو ساعت آینده است. در مرز دقیق مجاز؛ ساعت پس از قفل دوباره خوانده می‌شود. مهلت بر اساس زمان فعلی پیش از تغییر است، نه مقصد درخواست‌شده.

همان Appointment و code باقی می‌مانند؛ قیمت/مدت/بافر snapshot ثابت‌اند و تنها staff_name همراه staff_id قابل تغییر است. موتور availability موجود، برنامه زنده و snapshot تجاری توافق‌شده را ترکیب می‌کند؛ اشغال خود نوبت با شناسه آن از query حذف می‌شود. وضعیت انتشار/فعال‌بودن خدمت و صلاحیت متخصص همچنان زنده‌اند. لغو مشتری از انتشار مستقل است.

business lock مشترک با ایجاد/ویرایش برنامه، optimistic version و کلید idempotency به کار می‌روند. کنترل actor/resource قبل قفل و پیش از replay برقرار است. رویداد rescheduled با قبل/بعد، تغییر زمان/متخصص و تخصیص در همان transaction نوشته می‌شوند؛ هر شکست rollback می‌کند. FK تخصیص برای تغییر متخصص deferred می‌شود؛ exclusion فوری عدم تداخل باقی است. triggerها تغییر مالی/تماس/هویت نوبت و تغییر تاریخچه را همچنان رد می‌کنند و ارتباط رویداد با قبل/بعد را می‌آزمایند.

Port و adapter مستقل تغییرات در همان feature bookings هستند؛ ایجاد/خواندن پایه و mutation hook موجود بازاستفاده می‌شوند. تاریخچه محدود و مجاز، نقش انجام‌دهنده را نمایش می‌دهد و actor_id را افشا نمی‌کند. نسخه جاری به‌جای پاسخ تاریخی با replay/resolve بازخوانی می‌شود؛ UI فقط وضعیت معتبر دریافتی را گزارش می‌کند.

schema افزایشی است؛ migrationهای قبلی تغییر نمی‌کنند. خدمات مالی، auth، ارسال اعلان و تغییر توسط مالک وارد این تصمیم نمی‌شوند. تست واقعی DB و مرورگر شرط تحویل‌اند.
