# موجودی رابط اسپرینت۷

رنگ/تایپوگرافی/فاصله از design-system/tokens.css؛ موبایل agenda کارت و فرم تک‌ستونه. CTA حداقل۴۴ و input حداقل۱۶px؛ اطلاعات زمان/مبلغ مهم‌تر از متن کمکی‌اند. وضعیت دارای متن است.

- Checkout: loading خلاصه تازه، انتخاب ازدست‌رفته با بازگشت، فرم نام/موبایل، قوانین قبل CTA، ثبت در جریان، نتیجه نامشخص با بررسی همان کلید، قیمت تازه با تأیید مجدد؛ فرم در refresh خلاصه reset نمی‌شود.
- Receipt/detail: عنوان وضعیت، کد، تاریخ/شروع/پایان، متخصص/خدمت/مبلغ توافقی، آدرس و تماس، سیاست هماهنگی. لغو فقط مالک در صفحه خصوصی، با دلیل و تأیید جدا.
- My appointments: آینده/گذشته، صفحه‌بندی، loading/empty/read error، refresh و focus.
- Agenda: روز تهران با نمایش شمسی، عقب/امروز/جلو، فیلتر متخصص، کارت ساعت/نام/خدمت/وضعیت/منبع، آخرین دریافت و refresh؛ خطای refresh فهرست قبلی را برای همان فیلتر نگه می‌دارد و خطا را نشان می‌دهد.
- Manual: انتخاب خدمت/متخصص/روز/slot از ظرفیت مشترک؛ نام لازم، موبایل اختیاری؛ استثنای notice فقط با دلیل. هیچ اتصال از روی شماره انجام نمی‌شود.

فولدر bookings: api برای انتقال/decoder، model برای نوع/فرمت/انتخاب، hooks برای read/mutation/checkout، components برای screen و اجزای مشترک. routeها فقط پارامتر و Suspense/Gate را ترکیب می‌کنند. پالت/کتابخانه تقویم دوم نداریم.

## اصلاح مسیر شروع کار پس از تست دستی

صفحه مشخصات سالن، BookingReadiness را با API موجود publication نمایش می‌دهد: وضعیت واقعی عمومی‌بودن، نقص‌های قابل اقدام و مسیر انتشار یا صفحه عمومی، همراه لینک دفتر مشتریان. PublicationIssues در این کارت و صفحه انتشار مشترک است؛ قوانین آمادگی همچنان فقط در سرورند.

AccountGate می‌تواند guestContext عمومی دریافت کند؛ checkout قبل از ورود، انتخاب و عدم ثبت را توضیح می‌دهد. CheckoutSummary در حالت ناشناس و فرم ثبت مشترک است. ورود و بازخوانی availability پیش از ثبت نهایی حفظ شده‌اند. «نوبت‌های من» مراجعه شخصی است و دفتر سالن، نوبت مشتریان همان سالن و روز انتخاب‌شده را دارد.
