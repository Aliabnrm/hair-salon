# رابط اسپرینت۹ — دفتر عملیات سالن

دفتر فعلی `/manage/{businessId}/appointments` گسترش می‌یابد؛ route جدید و سیستم طراحی جدا ساخته نشده است. useAgenda انتخاب روز/۷روز، متخصص، وضعیت و cursor و دریافت داده را هماهنگ می‌کند؛ AgendaSummary/OutcomeForm/ScheduleBlocks/Form/Card مسئولیت جدا دارند. Button/TextField/SelectControl/DayPicker و tokenهای petrol/sand/surface موجود reuse می‌شوند. DayPicker اکنون today صریح دارد تا ابتدای بازه تاریخی به‌اشتباه «امروز» نام نگیرد.

خلاصه، کل بازه و متخصص را پیش از فیلتر وضعیت و pagination نشان می‌دهد؛ label این مبنا را توضیح می‌دهد. confirmed گذشته «منتظر ثبت نتیجه» است؛ خودکار no_show نمی‌شود. فهرست هفته از روز انتخابی۷روز را با تاریخ هر کارت نشان می‌دهد، روی موبایل grid متراکم یا drag/drop ندارد. فرم نتیجه فقط مالک است؛ زمان مجاز از checked_at سرور برای راهنمای رابط خوانده می‌شود و مجوز نهایی سروری است. تغییر نتیجه با reason و سابقه مشخص و امکان بازگشت به confirmed انجام می‌شود.

مسدودی دلیل خصوصی دارد. کاربر روز را شمسی و ساعت را بر اساس تهران انتخاب می‌کند؛ تبدیل IANA با round-trip مستقل از timezone دستگاه است. اگر ساعت پایان جلوتر از شروع نیست، روز بعد صریح در preview معرفی می‌شود. ثبت/رفع مسدودی تأیید صریح دارد. سابقه رفع، علت و نام متخصص باقی است؛ تاریخچه خصوصی هر block بدون افشای actor_id نمایش داده می‌شود. حداکثر۲۰۰مورد و پیام محدودیت؛ برای مرور، انتخاب روز/متخصص قابل محدودکردن است.

useResourceMutation از hook رزرو موجود بعد از شکل‌گیری نیاز دوم استخراج شده است؛ outcome از همان wrapper رزرو و block از resolver مستقل استفاده می‌کنند. هنگام نتیجه مبهم فرم قفل می‌شود و فقط کلید تصادفی در sessionStorage است؛ علت/تماس/بدنه ذخیره نمی‌شود. نتیجه بازیابی‌شده وضعیت فعلی resource است، نه پاسخ تاریخی. با خطای refresh، آخرین داده همان filter حفظ و stale اعلام می‌شود؛ اقدام رفع روی داده کهنه غیرفعال است.

هدف لمس۴۴، input۱۶px، RTL، دسترسی کیبورد، متن۲۰۰٪ و عرض۳۲۰/۳۶۰/۳۹۰/۴۳۰/۱۲۸۰ معیار بررسی‌اند. نتیجه آزمون واقعی در گزارش۹ است؛ این سند ادعای audit کامل دسترس‌پذیری یا realtime ندارد.
