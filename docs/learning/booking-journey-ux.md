# بازطراحی مسیر پیدا کردن سالن تا ثبت نوبت

تاریخ: ۲۰۲۶-۱۱-۰۵. این اصلاح با درخواست کارفرما برای ساده‌کردن تجربه سالن عمومی و مسیرهای مرتبط اجرا شد؛ شروع اسپرینت بعدی نیست.

## مسئله و تصمیم طراحی

در صفحه سالن، دکمه «بررسی زمان‌ها» از اطلاعات سالن جدا بود و پس از اسکرول در دسترس نمی‌ماند. خدمات، معرفی، برنامه متخصصان و برنامه هفتگی وزن بصری تقریباً یکسان داشتند. در انتخاب زمان، تقویم بلند و متن‌های تکراری، ساعت‌های آزاد و اقدام بعدی را پایین صفحه می‌بردند. بازگشت از ورود نیز همیشه به حساب می‌رفت، حتی وقتی کاربر مشغول رزرو بود.

طراحی جدید سه گام قابل فهم دارد: **انتخاب خدمت، انتخاب زمان، ثبت نهایی**. در هر صفحه یک اقدام اصلی وجود دارد و جزئیات تکمیلی از آن جدا هستند. این نشانگر مراحل، به‌معنای ثبت نوبت نیست؛ قطعی‌شدن همچنان فقط با پاسخ موفق سرور و رسید انجام می‌شود.

| مسیر                           | تغییر و دلیل                                                                                                                                                                             |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                            | متن کوتاه‌تر و عنوان «خدمات و رزرو» روی کارت سالن، مقصد لینک را روشن می‌کند.                                                                                                             |
| `/salons/[businessId]`         | نام و محل سالن، سپس خدمات و قیمت‌ها؛ هر خدمت لینک مستقیم انتخاب زمان دارد. دکمه «انتخاب زمان و رزرو» در نوار اقدام باقی می‌ماند. معرفی، ساعات و تعطیلی‌ها بازشونده‌اند.                  |
| `/salons/[businessId]/times`   | انتخاب خدمت و متخصص فشرده‌تر، روزها در نوار افقی با ماه و روز هفته، ساعت‌ها در شبکه و ادامه رزرو کنار خلاصه انتخاب در نوار پایین. انتخاب روز فقط اسکرول افقی همان نوار را تغییر می‌دهد.  |
| `/salons/[businessId]/book`    | برای مهمان، توضیح کوتاه، انتخاب حفظ‌شده و ورود در نوار پایین؛ برای عضو، اطلاعات تماس و دکمه ثبت نهایی در دسترس. هزینه و پرداخت در سالن روشن‌اند.                                         |
| `/sign-in` و `/sign-up`        | برگشت متناسب با مقصد: ثبت‌نام به ورود، ورود به رزرو قبلی یا مقصد مجاز حساب/مدیریت.                                                                                                       |
| `/appointments` و جزئیات نوبت  | عنوان و متن کوتاه‌تر، جداسازی ورود به مدیریت سالن از نوبت‌های مشتری و هدر برگشت در صفحه رسید.                                                                                            |
| مسیرهای مدیریت سالن            | برگشت موجود و ناوبری بخش‌ها حفظ شدند؛ توضیح فنی تکراری بالای همه بخش‌ها حذف و متن دفتر نوبت‌ها و خصوصی‌بودن مدیریت اصلاح شد. انتخاب روز ثبت دستی نیز از تقویم مشترک جدید استفاده می‌کند. |
| پیش‌نمایش خصوصی و بررسی انتشار | اطلاعات سالن با همان اجزا نمایش داده می‌شود، اما اقدام رزرو و نشانگر مراحل ندارد.                                                                                                        |
| سالن ناموجود                   | حالت موجودِ «سالن در دسترس نیست» و لینک بازگشت، مقصد روشن دارد و حفظ شد.                                                                                                                 |

## فایل‌ها و نکته‌های پیاده‌سازی

- `frontend/src/components/layout/page-header.tsx`: هدر سبک با مقصد بازگشت مشخص و آیکن مناسب RTL؛ متن و دکمه برگشت در صفحه بلند در دسترس‌اند.
- `frontend/src/components/layout/page-action-bar.tsx` و `app-shell.tsx`: نوار اقدام با Portal در `#page-actions`، بین محتوای اسکرول‌شونده و ناوبری اصلی قرار می‌گیرد. این نوار بخشی از چیدمان است؛ روی دکمه‌ها یا محتوای صفحه نمی‌افتد و هنگام عوض‌شدن مسیر، Portal قبلی پاک می‌شود.
- `frontend/src/components/ui/booking-progress.tsx`: نشانگر سه مرحله با `aria-current="step"`؛ بدون state یا مسیر ساختگی.
- `frontend/src/features/public-catalog/components/`: `public-profile.tsx` ترکیب‌کننده معرفی است، `salon-service-card.tsx` کارت انتخاب خدمت و `salon-details.tsx` اطلاعات تکمیلی را نشان می‌دهند. `bookingEnabled` فقط در route عمومی فعال است؛ پیش‌نمایش خصوصی مجوز رزرو دریافت نمی‌کند.
- `frontend/src/features/availability/components/`: منطق دریافت ظرفیت و پاک‌شدن انتخاب قدیمی در hook موجود مانده است. تغییرها مربوط به ترتیب، متن، تقویم و محل اقدام هستند.
- `frontend/src/features/bookings/components/checkout-screen.tsx`: دکمه پایین با `form="online-booking-form"` به فرم واقعی وصل است. کلیک دکمه همچنان اعتبارسنجی مرورگر و `onSubmit` همان فرم را اجرا می‌کند؛ موقعیت بصری دکمه، صحت ارسال را عوض نمی‌کند.
- `frontend/src/features/identity/components/auth-back-link.tsx`: مقصد برگشت از `safeReturnTo` موجود می‌گذرد؛ پذیرش URL دلخواه یا برگشت تصادفی به سایت بیرونی اضافه نشده است.
- `frontend/src/features/discovery/hooks/use-discovery-filters.ts`: فیلترهای همان صفحه با History API مرورگر تغییر می‌کنند؛ طبق راهنمای نسخه نصب‌شده Next.js، `pushState` با `useSearchParams` هماهنگ است. داده همچنان با hook دریافت می‌شود. در قطع اینترنت، تغییر فیلتر دیگر به ناوبری سروری و صفحه خطای مرورگر وابسته نیست؛ خطا و تلاش دوباره داخل برنامه می‌مانند. برگشت/جلو و لینک اشتراک‌پذیر نیز حفظ شده‌اند.

مثال: انتخاب «کوتاهی مو» در صفحه سالن، `service_id` را در لینک زمان‌ها می‌گذارد. پس از انتخاب روز و ساعت، لینک ادامه شامل همان خدمت، متخصص و ساعت شروع است. ورود و ثبت‌نام این انتخاب را در `returnTo` حفظ می‌کنند؛ تا زدن دکمه ثبت نهایی، نوبتی ساخته نمی‌شود.

## بررسی کیفیت

تست رفتار جدید در `frontend/e2e/availability.spec.ts`، دیده‌شدن اقدام اصلی در ابتدا و انتهای صفحه در عرض‌های ۳۲۰، ۳۶۰، ۳۹۰، ۴۳۰ و ۱۴۴۰، نبود هم‌پوشانی با ناوبری، انتخاب مستقیم خدمت، پاک‌شدن نوار قبلی و برگشت بین رزرو/ورود/ثبت‌نام را بررسی می‌کند. تست‌های موجود انتخاب زمان، شبکه و داده کهنه، بزرگ‌نمایی ۲۰۰ درصد، ثبت واقعی، رقابت ظرفیت و بازیابی رسید نیز مرجع حفظ رفتارند.

بررسی ۳۲۰ پیکسل با متن ۲۰۰ درصد دو ایراد عرض را آشکار کرد: لینک بخش‌های سالن و متن نشانگر مراحل. لینک‌ها قابلیت شکستن متن گرفتند و نشانگر در موبایل، شماره را بالای عنوان قرار می‌دهد. تست قطع اینترنت کاوش نیز ناوبری کامل مرورگر را آشکار کرد که با History API اصلاح شد. این بررسی‌ها از تست حذف یا ضعیف نشدند.

تصویرهای این بررسی در `work/booking-journey-ux/` هستند؛ فایل واسط و داده تست وارد Git نمی‌شوند. همه نوشتن‌های مرورگر در دیتابیس اختصاصی تست انجام می‌شوند. بررسی UI روی داده واقعی سالن کارفرما نوبت یا حساب تازه‌ای ثبت نمی‌کند.

این بازطراحی، احراز هویت، قانون ظرفیت، پرداخت آنلاین، لغو آنلاین مشتری یا ارسال پیامک جدیدی اضافه نمی‌کند. هزینه خدمت در سالن پرداخت می‌شود و برای لغو یا تغییر، تماس با سالن لازم است.

## نتیجه اجرای واقعی

اجرای نهایی با Node.js `24.22.2` و pnpm `12.16.1` در محیط محلی انجام شد:

| بررسی                                                                      | نتیجه                          |
| -------------------------------------------------------------------------- | ------------------------------ |
| `pnpm --filter @hair-salon/frontend run typecheck`                         | موفق                           |
| `pnpm --filter @hair-salon/frontend run lint`                              | موفق، بدون ویرایش خودکار       |
| `pnpm --filter @hair-salon/frontend run format:check`                      | موفق                           |
| `pnpm --filter @hair-salon/frontend run test`                              | ۴۳ تست در ۱۰ فایل موفق         |
| `pnpm --filter @hair-salon/frontend exec playwright test --max-failures=1` | هر ۴۶ تست موفق، حدود ۱٫۷ دقیقه |
| `git diff --check`                                                         | موفق                           |

اجرای مرورگر با `PLAYWRIGHT_CHANNEL=chrome` و `TEST_DATABASE_URL` اختصاصی انجام شد؛ Chromium همراه Playwright در این محیط نصب نبود. fixture مرورگر، نسخه مستقل Next را با `next build --webpack` ساخت و API و PostgreSQL واقعی تست را به آن متصل کرد. ساخت مستقل باعث شد سرور توسعه و داده سالن کارفرما دست‌نخورده بمانند. Typecheck و lint پس از اصلاح hook فیلتر کاوش نیز دوباره اجرا و موفق شدند؛ قالب‌بندی همان hook و سندهای مرتبط جداگانه بررسی شد.

تصویرهای نسخه نهایی در عرض ۳۲۰ و ۳۹۰، انتخاب ساعت، ادامه رزرو و ورود بررسی شدند. محدوده این اجرای تست، رابط و جریان مرورگر است؛ اجرای کامل `pnpm run check` و CI راه‌دور در این اصلاح انجام نشده است.

پس از اجرای کامل، کنترل دیده‌شدن کامل دکمه رزرو و ناوبری اصلی در عرض ۳۲۰ با متن ۲۰۰ درصد نیز به تست انتشار افزوده شد؛ اجرای مجدد `publication.spec.ts` با هر دو تست موفق بود. تصویر همین حالت پس از تثبیت چیدمان بررسی شد و دکمه، متن و ناوبری داخل عرض صفحه باقی ماندند. lint و format-check نهایی فرانت‌اند و قالب‌بندی سندها نیز موفق بودند.

تغییرها روی شاخه `fix/booking-journey-ux` محلی باقی ماندند و تغییرهای قبلی پروژه حفظ شدند. هیچ commit یا push انجام نشد. پیام پیشنهادی commit پس از بررسی کارفرما:

```text
fix(ux): simplify salon discovery and booking navigation
```
