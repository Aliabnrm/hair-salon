# اسپرینت ۵ — انتشار بررسی‌شده و کاتالوگ واقعی

تاریخ: ۲۰۲۶-۱۱-۰۲؛ محدوده با پرامپت ارسالی کارفرما مصوب است. پیاده‌سازی در شاخه `feat/sprint-05-public-catalog`، اجرا و با check کامل بررسی شده است؛ [گزارش واقعی](sprint-05-report.md) مرجع نتیجه است. مرجع دستور، [پرامپت اجرایی](../../prompts/sprint-05.md) و تصمیم [ADR-009](../../architecture/adr/ADR-009-reviewed-public-catalog.md) است. این سند جای پیشنهاد قدیمی تأیید ایمیل/reset را گرفته است.

## هدف و محدوده

مالک اطلاعات واقعی سالن را تکمیل می‌کند، نقص‌های آمادگی و پیش‌نمایش خصوصی را می‌بیند و با رضایت به نسخه محتوا درخواست انتشار می‌فرستد. reviewer مستقل با دسترسی صریح DB، نسخه جاری را تأیید یا با دلیل رد می‌کند. مشتری ناشناس فقط published را در فهرست، شهرها و پروفایل می‌بیند. ورود ایمیل/رمز، نشست و خروج حفظ می‌شوند؛ تأیید ایمیل، بازیابی رمز، ارسال ایمیل/SMS، OTP و MFA خارج این اسپرینت‌اند. email_verified_at تغییر مصنوعی نمی‌کند.

رزرو، availability، پرداخت، عکس/آپلود، امتیاز/نظر، نقشه/فاصله، CRM، حساب متخصص، استقرار و اسپرینت۶ خارج محدوده‌اند. شهر پایلوت تعیین نشده و در UI hard-code نمی‌شود.

## برش‌های همین اسپرینت

1. migration0004: دسته مرجع، معرفی کوتاه، public_visible پیش‌فرض false، revision و چرخه انتشار؛ حفظ داده‌های قبلی.
2. آمادگی سروری، projection مشترک allowlist و پیش‌نمایش خصوصی.
3. درخواست/رضایت، انصراف، invalidation اتمیک همه writeهای محتوا.
4. reviewer مستقل، CLI توسعه/تست، تأیید/رد/تعلیق و تاریخچه.
5. API عمومی no-store، فیلتر نرمال‌شده، مکان واقعی و keyset pagination.
6. رابط مالک/reviewer، پروفایل و اتصال کشف به داده واقعی؛ حذف نمونه از importهای runtime.
7. آزمون واقعی migration، حریم خصوصی، هم‌زمانی، مرورگر، بررسی نهایی و آموزش.

## تصمیم‌های تثبیت‌شده

یک state در businesses، بدون snapshot عمومی موازی. هر write تازه و موفق، content_revision و publication_version را افزایش می‌دهد؛ published/pending به draft برمی‌گردند، suspended حفظ می‌شود. تغییر state همچنین version تنظیمات را تغییر می‌دهد. نسخه تنظیمات، ساعات و entity فرزند بازتعریف نشده‌اند. درخواست پس از تعلیق به اصلاح محتوا نیاز دارد.

اعطای reviewer واقعی فقط با معرفی حساب توسط کارفرماست؛ در اجرای خودکار فقط حساب‌های DB موقت استفاده می‌شوند. CLI در development/test و با User ID موجود/دلیل اجرا می‌شود. commit/push/PR/merge/deploy این اسپرینت انجام نمی‌شود؛ تغییرهای محلی برای مرور کارفرما باقی می‌مانند.

نتیجه آزمون و محدودیت واقعی فقط در [گزارش](sprint-05-report.md) ثبت می‌شود؛ متن طرح، شاهد عبور آزمون نیست.
