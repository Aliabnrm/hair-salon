# اسپرینت ۶ — انتخاب خدمت و زمان‌های قابل ارائه

تاریخ: ۲۰۲۶-۱۱-۰۳. محدوده و مقادیر اولیه با پیام «تاییده پرامپت رو آماده‌سازی کن» تأیید شدند. **وضعیت: طرح مصوب و پرامپت آماده؛ پیاده‌سازی آغاز نشده است.** مرجع تفصیلی اجرا [پرامپت۶](../../prompts/sprint-06.md) است.

## هدف قابل مشاهده

مشتری ناشناس از صفحه عمومی یک سالن منتشرشده، خدمت، متخصص مشخص یا «اولین متخصص آزاد» و روز شمسی را انتخاب کند؛ زمان‌های معتبر طبق برنامه واقعی را ببیند و خلاصه انتخابش را مرور کند. ثبت قطعی رزرو خروجی اسپرینت۷ است.

## تصمیم‌های مصوب

- D-015 / Q-15: نسخه اول برای هر دو گروه زنانه/مردانه، محدود به یک خدمت پیوسته با یک متخصص و ظرفیت یک است؛ چندمرحله، چندخدمت و منابع مشترک بعداً بررسی می‌شوند.
- D-016: گام شروع۱۵دقیقه روی نیمه‌شب محلی، حداقل فاصله۶۰دقیقه از ساعت سرور و افق۳۰روز تقویمی شامل امروز تهران تا today+29.
- هر query حداکثرهفت روز؛ تاریخ API میلادی محلی ISO، نمایش شمسی/۲۴ساعته و timezone تهران با تبدیل واقعی.
- ساعات و تعطیلی مؤثر سالن و متخصص، مدت و بافرهای قبل/بعد از DB واقعی خوانده و در یک موتور خالص محاسبه شوند.
- نبود مدل رزرو/دفتر اشغال در baseline۵ صریح باشد: `availability_basis=schedule_only` و `booking_enabled=false`. انتخاب ساعت تضمین یا ثبت ظرفیت نیست.
- API عمومی خواندنی و no-store، بدون شرط ورود یا تغییر auth فعلی. ساخت جدول رزرو/مسدودی یا سرویس fake در این برش مجاز نیست.

حمایت از کسر busy interval در ورودی موتور و تست آن، بخشی از قانون زمانی است؛ اتصال اشغال واقعی، منع تداخل اتمیک، ثبت رزرو و اعلان متعلق به مراحل بعد هستند. خطای DB به اشغال خالی یا فهرست خالی تبدیل نمی‌شود.

## محدوده و معماری

availability خواندنی در feature موجود salon-management، با Domain/Application/Reader/HTTP مشخص؛ route و feature فرانت مستقل برای انتخاب و URL state. reuse ابزارهای بازه، کلاینت، Design System و تبدیل پول/تاریخ موجود با بررسی رفتار واقعی. dependency تازه فقط برای نیاز اثبات‌شده تبدیل timezone و با بررسی نسخه/منبع مجاز است.

مسیر هدف رابط `/salons/[businessId]/times`؛ API هدف `GET /api/v1/catalog/salons/{businessId}/availability`. قرارداد دقیق query/DTO/خطا، ساختار فایل، قواعد مرزی و تست‌ها در prompt است. گزارش، درس و ADR اجرایی باید پس از شروع واقعی و با شواهد مناسب ایجاد شوند؛ این طرح گزارش انجام کار نیست.

## پیش‌نیاز Git و اجرای بعدی

در بررسی واقعی این نوبت، `git fetch origin` موفق و dev با origin/dev همسان در `c8bcaf6` بود. کد و اسناد۵ هنوز روی `feat/sprint-05-public-catalog` ثبت نشده‌اند. برای حفظ این تغییرها، dev checkout/pull و شاخه تازه انجام نشد؛ فقط همین مدارک مرتبط در شاخه فعلی آماده شدند. فایل‌های محصول تغییر نکردند.
