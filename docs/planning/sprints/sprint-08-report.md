# گزارش اسپرینت۸ — مدیریت نوبت مشتری

۲۰۲۶-۱۱-۰۶؛ شاخه feat/sprint-08-customer-booking-management از dev به‌روز0384913 با درخت اولیه پاک. دستور آماده‌سازی و اجرای کارفرما مرجع تصویب [طرح](sprint-08-plan.md) و [پرامپت](../../prompts/sprint-08.md) است. commit/push/PR/merge/deploy انجام نشده‌اند.

## خروجی

لغو توسط مشتری تا دو ساعت پیش از شروع، جابه‌جایی اتمیک همان نوبت/خدمت/سالن با متخصص مجاز و تاریخچه مشترک اضافه شدند. کد پیگیری و قیمت/مدت/بافر حفظ می‌شوند. جزئیات نوبت سیاست و مهلت را روشن نشان می‌دهد؛ پس از مهلت مسیر تماس باقی است. دفتر سالن پس از تازه‌سازی/بازگشت focus همان تغییر را نشان می‌دهد. تغییر مالک، SMS/auth/پرداخت و تقویم پیشرفته در این اسپرینت اجرا نشده‌اند.

## معماری و بررسی

BookingChangesService/Store و adapter در همان feature bookings، قانون خالص booking-changes، transaction مشترک و موتور availability موجود استفاده شدند. read-only snapshot برای جزئیات/تاریخچه یکپارچه است؛ تاریخچه۵۰رویداد اخیر و نقش انجام‌دهنده را بدون actor_id برمی‌گرداند. cancelLockedBooking منطق ذخیره لغو مشترک را نگه می‌دارد. مرجع تصمیم [ADR-014](../../architecture/adr/ADR-014-customer-booking-changes.md)، موجودی [رابط۸](../../architecture/sprint-08-ui.md) و [درس۸](../../learning/sprint-08.md) هستند.

Migration0006 فقط فیلد details/action و trigger/FK لازم را می‌افزاید؛ فایل‌های migration قبلی بازنویسی نشده‌اند. قید فوری عدم تداخل باقی است. حفاظت داده قبلی و تغییرناپذیری تاریخچه با PostgreSQL واقعی بررسی شدند.

## نتیجه بررسی نهایی

فرمان `PLAYWRIGHT_CHANNEL=chrome node work/run-sprint-07-check.mjs run check` با خروجی صفر پایان یافت. این runner محلیِ نادیده‌گرفته‌شده، فرمان واقعی `pnpm run check` را با دیتابیس اختصاصی تست اجرا می‌کند. build هر دو workspace، typecheck، lint و format:check موفق بودند. مجموع۳۷۰تست موفق:

| گروه                             | تعداد موفق |
| -------------------------------- | ---------- |
| unit بک‌اند                      | ۱۱۸        |
| unit فرانت                       | ۴۵         |
| قرارداد HTTP                     | ۵۶         |
| integration روی PostgreSQL واقعی | ۱۰۱        |
| مرورگر Chrome                    | ۵۰         |

پوشش مهم: مرز دقیق دو ساعت، بررسی دوباره ساعت پس از انتظار قفل، مالکیت/tenant، حفظ توافق پس از تغییر کاتالوگ، جابه‌جایی روی بخشی از ظرفیت قبلی خود، رقابت جابه‌جایی/لغو/رزرو تازه، rollback مقصد نامعتبر یا پرشده، replay هم‌زمان، جلوگیری از دست‌کاری مستقیم تاریخچه/تخصیص در DB و ارتقا از migrationهای دقیق اسپرینت۷ با نوبت و intent موجود.

مرورگر جریان مشتری→جابه‌جایی→دفتر مالک در روز جدید و تاریخچه→لغو مشتری→آزادشدن ظرفیت را تأیید کرد. قطع پاسخ پس از commit و بازیابی پس از reload، اشغال مقصد پس از انتخاب، عرض‌های۳۲۰/۳۶۰/۳۹۰/۴۳۰/۱۲۸۰، متن۲۰۰٪، focus کیبورد و پایان مهلت نیز بررسی شدند. تصاویر بررسی محلی در `work/sprint-08-screens/` نادیده‌گرفته‌شده‌اند.

اجرای نخست DB به دلیل خاموش‌بودن PostgreSQL و بررسی نخست مرورگر به دلیل جاافتادن مسیرهای جدید در allowlist فرانت شکست خوردند؛ هر دو اصلاح و دوباره بررسی شدند. ابهام alias در trigger SQL نیز با تست واقعی یافت و اصلاح شد. نتیجه نهایی بالا مربوط به اجرای کامل پس از اصلاح‌هاست.

## اجرای محلی و حفظ داده

قبل از migration محیط توسعه، backup با دسترسی محدود۰۶۰۰ در `work/sprint-08-local-before.dump` گرفته شد. migration واقعی اجرا و تعداد/اثر انگشت همه نوبت‌ها، تخصیص‌ها، ستون‌های قبلی رویدادها و intentها قبل/بعد مقایسه شدند؛ همگی بدون تغییر بودند. نتیجه بدون داده شخصی در `work/sprint-08-local-result.json` ثبت است؛ backup و ابزارهای محلی وارد Git نمی‌شوند.

فرانت در `http://localhost:3000` و API در پورت۳۰۰۱ راه‌اندازی شدند. بررسی زنده پس از راه‌اندازی، آمادگی هر دو، حفاظت مسیر جابه‌جایی مهمان و حفظ مسیر بازگشت هنگام ورود را تأیید کرد؛ خطای صفحه صفر بود و هیچ نوبت واقعی در این بررسی تغییر نکرد. typeهای Next نیز با `next typegen` تولید شدند؛ فایل تولیدی دستی ویرایش نشد.

برای پذیرش دستی: با حساب مشتری، «نوبت‌های من»→جزئیات یک نوبت با بیش از دو ساعت فاصله→تغییر زمان→انتخاب و تأیید. با حساب مالک همان سالن، روز جدید را در دفتر انتخاب و تازه‌سازی کن؛ کد پیگیری و تاریخچه یکسان‌اند. سپس لغو مشتری و آزادشدن ظرفیت را بررسی کن. مهلت، وضعیت و دسترسی باید شرایط واقعی نوبت را داشته باشند؛ رزرو دستی مالک صرفاً با تطبیق شماره به حساب مشتری متصل نمی‌شود.

CI راه دور، اجرای Docker، تست بار و استقرار production در این تحویل اجرا نشده‌اند. ارسال SMS/push، تغییر وقت توسط مالک و تقویم پیشرفته خارج از محدوده‌اند. هماهنگی دفتر با بازخوانی/focus است؛ اعلان لحظه‌ای اضافه نشده است.
