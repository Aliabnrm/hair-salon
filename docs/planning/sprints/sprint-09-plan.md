# طرح اسپرینت۹ — عملیات روزانه سالن

۲۰۲۶-۱۱-۰۶؛ مصوب با درخواست آماده‌سازی و اجرای کارفرما. هدف: تکمیل چرخه مراجعه و مدیریت ظرفیت روزانه با بازاستفاده معماری جاری. وضعیت اجرا فقط در گزارش نهایی ثبت می‌شود.

## دامنه و معیار پذیرش

- مالک، پس از پایان نوبت confirmed→completed و از شروع+۱۵دقیقه confirmed→no_show را صریح ثبت می‌کند؛ گذر زمان خودکار نتیجه ایجاد نمی‌کند. اصلاح completed/no_show به confirmed یا نتیجه دیگر با دلیل۳..۳۰۰ نویسه، نسخه تازه و رویداد immutable انجام می‌شود. لغوشده قابل اصلاح نیست. ثبت نتیجه و اصلاح، اشغال زمان توافق‌شده را آزاد نمی‌کنند؛ عدم حضور، ظرفیت پیش از پایان را ناخواسته قابل رزرو نمی‌کند. اقدام سروری فقط مالک مجاز است.
- مسدودی یک متخصص فعال، با دلیل خصوصی، بازه آینده حداکثر۲۴ساعت در افق۳۰روز و گام۱۵دقیقه؛ خارج ساعت کاری هم مجاز، ولی هم‌پوشانی با هر allocation فعال ممنوع. رفع مسدودی با دلیل و version، بدون حذف سابقه. مسدودی/رزرو/تغییر برنامه از قفل مشترک سالن استفاده می‌کنند؛ exclusion DB تضمین نهایی است. علت مسدودی در API عمومی یا مشتری افشا نمی‌شود.
- دفتر روز یا بازه۷روزه از تاریخ انتخابی، فیلتر متخصص/وضعیت، تاریخ شمسی و زمان تهران، خلاصه شمارش کل بازه پیش از pagination و نمایش مسدودی‌ها. ثبت دستی و لغو موجود بازنویسی نمی‌شوند. شمارش «منتظر ثبت نتیجه» فقط confirmed گذشته است؛ به معنی عدم حضور نیست.
- UI بر پایه petrol/sand/surface و اجزای موجود، هدف لمس۴۴px، input۱۶px، RTL، عرض۳۲۰تا۴۳۰ و دسکتاپ؛ هفته به صورت فهرست قابل استفاده در موبایل، بدون drag/drop. loading/error/empty، حفظ داده در refresh ناموفق، تأیید صریح و بازیابی نتیجه مبهم شبکه لازم‌اند.
- migration افزایشی با حفظ نوبت/تاریخچه/کلیدهای قبلی؛ تست DB واقعی race مسدودی/رزرو، tenant، idempotency، قیود مستقیم و upgrade. تست مرورگر مسیر مالک و مشتری، خلاصه/فیلتر/هفته و موبایل. check کامل، گزارش واقعی و درس فارسی الزامی‌اند.

## معماری و مرز

همان Modular Monolith: bookings مالک Appointment/Allocation/Block؛ domain قانون، application سناریو، persistence تراکنش و HTTP ورودی. وضعیت جدید در decoder، قرارداد، تاریخچه و UI مشتری نیز پوشش داده می‌شود. زمان از Clock تزریق می‌شود و پس از قفل بازخوانی می‌شود. migrationهای پیشین تغییر نمی‌کنند. بدون dependency جدید، auth/SMS/پرداخت/CRM/حساب پذیرش/تغییر وقت مالک/اسپرینت۱۰/deploy. commit/push با کارفرماست.
