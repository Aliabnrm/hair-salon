# محدوده پیشنهادی MVP
تمام اولویت‌ها پیشنهادند؛ توسعه تا تصویب محدوده، نیازمندی‌های اصلی و طرح فنی شروع نمی‌شود.

| اولویت | داخل محدوده | دلیل و مرز |
|---|---|---|
| P0 | حساب موبایلی، نشست امن، مجوزهای سالن و پشتیبانی | پیش‌نیاز رزرو و حفاظت داده؛ مدیران دسترسی حساس نیازمند عامل دوم |
| P0 | پروفایل پیش‌نویس→بازبینی→انتشار/تعلیق | اعتماد حداقلی؛ بررسی دستی کافی برای پایلوت |
| P0 | خدمات قیمت/مدت ثابت، متخصصان، ساعات، استراحت و تعطیلی موردی | پایه زمان‌بندی؛ هر رزرو یک خدمت و یک متخصص |
| P0 | جست‌وجوی نام/دسته/شهر/محله و لینک رزرو | کشف حداقلی؛ بدون شعاع، نقشه، فیلتر زمان آزاد سراسری یا رتبه امتیاز |
| P0 | نمایش وقت، ثبت بدون تداخل، لغو/جابجایی و تاریخچه | ارزش اصلی؛ پرداخت، hold و تأیید دستی نداریم |
| P0 | تقویم روز، فهرست هفته، متخصص، ثبت دستی و زمان مسدود | یک تقویم مشترک؛ drag-and-drop الزامی نیست |
| P0 | پرونده پایه مشتری و یادداشت کاری خصوصی سالن | داده حداقلی؛ بدون سلامت، اطلاعات مالی یا رضایت بازاریابی پیش‌فرض |
| P0 | تأیید/تغییر/لغو و یک یادآوری SMS؛ وضعیت داخل صفحه رزرو | اعلان مستقل از صحت ثبت؛ ایمیل/push الزامی نیست |
| P0 | گزارش شمارش رزرو و وضعیت‌ها، پشتیبانی و نظارت پایه | بدون ادعای درآمد وصول‌شده |

P1: نظرات مراجعه تأییدشده، رزرو مجدد یک‌کلیکی، علاقه‌مندی، انتظار، بیعانه با تطبیق و بازپرداخت، گزارش بازگشت مشتری، تخفیف، وفاداری و رزرو تکراری. ترتیب آن‌ها با داده پایلوت تعیین می‌شود؛ اگر بیعانه شرط پذیرش سالن باشد، بازتعریف P0 و برآورد مجدد لازم است.

P2: چندشعبه و تخصیص مشترک کارکنان بین سالن‌ها، منابع مشترک/ظرفیت گروهی، چندخدمت یا خدمات مرحله‌ای، POS، کالا/انبار، حقوق و پورسانت، native، AI و یکپارچگی‌های گسترده.

مرز کارکنان: یک متخصص در P0 فقط در یک کسب‌وکار فعال ارائه خدمت دارد؛ یک کاربر می‌تواند مشتری سالن دیگری باشد. عضویت مدیریتی چند سالن، اگر تأیید شود، با tenant صریح انجام می‌شود؛ تقویم متخصص بین سالن‌ها هنوز حل نشده است.

معیار خروج از پایلوت: شواهد استفاده روزانه، صفر تداخل معتبر، امکان بازیابی و کنترل دسترسی تأییدشده؛ سپس تصمیم ادامه بر اساس نرخ فعال‌ماندن سالن، تکمیل جریان و هزینه پشتیبانی. معیار بازار از پیش اثبات‌شده نیست. [نقشه راه](../planning/roadmap.md).
