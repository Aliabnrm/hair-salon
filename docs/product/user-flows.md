# جریان‌های کاربری و استثناها
## رزرو مشتری
جست‌وجو/لینک مستقیم ← پروفایل منتشرشده ← خدمت با قیمت/مدت ثابت ← متخصص مشخص یا اولین متخصص آزاد ← روز شمسی و وقت محلی ← OTP در صورت نداشتن نشست ← خلاصه قیمت، نشانی و سیاست ← ثبت ← شماره پیگیری و وضعیت confirmed.

استثناها: بدون خدمت/متخصص فعال یا بدون وقت، empty state و انتخاب روز دیگر؛ OTP دیررس، زمان‌سنج ارسال مجدد و نگهداشت انتخاب؛ slot پس از ورود پر شده، 409 و وقت‌های تازه؛ قیمت/سیاست عوض شده، خلاصه جدید و تأیید دوباره؛ قطع شبکه بعد از ثبت، همان کلید درخواست بررسی/تکرار شود و قبل از پاسخ معتبر موفقیت نشان ندهیم. هیچ slot هنگام OTP نگه داشته نمی‌شود.

«اولین متخصص آزاد»: انتخاب روز/ساعت از اجتماع slotهای واجد شرایط؛ سرور هنگام ثبت میان متخصصان مجاز با ترتیب قطعی، یکی را قفل و انتخاب می‌کند؛ اگر اولی اشغال شده گزینه بعدی در همان زمان امتحان می‌شود؛ شناسه تخصیص نهایی در تأیید نمایش داده شود. tie-break پیشنهادی شناسه ثابت است و fairness هنوز نیازمند تصمیم است.

## تغییر و لغو
حساب مشتری ← رزرو خود ← نمایش سیاست snapshot ← وقت جایگزین ← تأیید ← تغییر اتمیک همان رزرو و افزایش version ← اعلان. شکست یا تداخل، رزرو قبلی را حفظ می‌کند. مشتری بعد از مهلت مجاز، راه تماس با سالن می‌بیند. لغو معتبر ظرفیت را آزاد می‌کند؛ تکرار لغو برای همان وضعیت نتیجه فعلی را می‌دهد. لغو و تغییر هم‌زمان با version کنترل می‌شوند.

## راه‌اندازی کسب‌وکار
ورود مالک ← ساخت draft ← آدرس/تماس عمومی با تأیید مالک ← یک یا چند متخصص ← خدمت و اتصال آن به متخصص ← برنامه و تعطیلی ← سیاست ← پیش‌نمایش ← درخواست بررسی ← تأیید پشتیبان ← published. ناقص بودن شماره تماس/خدمت/برنامه مانع ارسال است. رد با دلیل به draft برمی‌گردد؛ تغییر آدرس/تماس عمومی/دسته پروفایل منتشرشده آن را برای بررسی دوباره in_review می‌کند و تا تأیید، رزرو جدید متوقف می‌شود؛ رزروهای موجود محفوظ‌اند. suspended رزرو جدید نمی‌گیرد، رزرو موجود خودکار لغو نمی‌شود و پشتیبانی پیگیری می‌کند.

## عملیات روزانه
انتخاب روز و متخصص ← تقویم ← رزرو دستی با نام و موبایل اختیاری ← بررسی همان قواعد زمان‌بندی ← confirmed با source=manual. موبایل بدون OTP به حساب جهانی مشتری وصل نمی‌شود. لغو/تغییر/تکمیل/عدم حضور از جزئیات با مجوز و audit انجام می‌شود. ثبت فوری برای مراجعه حضوری مجاز است، اما رزرو در گذشته و override تداخل ممنوع؛ استثنای حداقل فاصله فقط برای مالک/پذیرش با ثبت دلیل.

## تغییر برنامه و مسدودی
مالک بازه جدید را می‌بیند ← سرور تعارض رزروها را نشان می‌دهد ← در تعارض ذخیره رد می‌شود ← مالک ابتدا با مشتری هماهنگ و رزرو را جداگانه جابه‌جا/لغو می‌کند ← برنامه جدید ذخیره می‌شود. ایجاد مرخصی و رزرو هم‌زمان تحت همان قفل متخصص‌اند؛ هیچ‌کدام دیگری را بی‌صدا حذف نمی‌کند.

## پشتیبانی و حریم خصوصی
ثبت شکایت/شماره پیگیری ← احراز نقش پشتیبان ← مشاهده حداقل داده ماسک‌شده ← در صورت ضرورت درخواست دسترسی با دلیل ← audit مشاهده و اقدام ← نتیجه به درخواست‌کننده. یادداشت خصوصی سالن و شماره مشتریان برای پشتیبانی عمومی باز نیست.
